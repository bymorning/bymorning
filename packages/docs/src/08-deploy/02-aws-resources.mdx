One `sst deploy` of the production stage creates 71 AWS resources. This inventory is taken from the recorded SST state of the production stage; the counts and configuration match what `infra/*.ts` declares.

Names in the **Logical name** column are the SST component names. They are stable across accounts and stages, so use them to match resources after deploying elsewhere.

Physical names and IDs (`vpc-…`, bucket names, ARNs) are generated per deployment and are deliberately omitted. Resources marked **production only** come from `bastion` and `nat: "ec2"` in `infra/server.ts`, which are enabled only when `$app.stage === "production"`.

## Outside

### Bootstrap

Created once per account and region on the first `sst deploy`, shared by every stage, and left in place by `sst remove`:

- S3 state bucket
- S3 asset bucket
- ECR repository `sst-asset` for the Gateway container image
- SSM parameters holding bootstrap metadata and the state encryption passphrase

### Service-linked

AWS creates these on first use if the deployer may call `iam:CreateServiceLinkedRole`; otherwise they must already exist:

| Role                                                 | Service                   |
| ---------------------------------------------------- | ------------------------- |
| `AWSServiceRoleForECS`                               | ECS service orchestration |
| `AWSServiceRoleForElasticLoadBalancing`              | Application Load Balancer |
| `AWSServiceRoleForRDS`                               | Aurora                    |
| `AWSServiceRoleForApplicationAutoScaling_ECSService` | ECS autoscaling           |
| `AWSServiceRoleForBedrockAgentCoreNetwork`           | AgentCore VPC networking  |

### Not created

No Route 53 or ACM resources exist because the stack does not attach a custom domain. Bedrock model access is an account-level setting, not a deployed resource.

## Inspect

The SST state file is the authoritative record of what a deploy created. Download it from the state bucket and list the AWS entries:

```sh
aws s3api get-object \
  --bucket <sst-state-bucket> \
  --key app/bymorning/<stage>.json \
  state.json

jq '
  .checkpoint.latest.resources[]
  | select(.type | startswith("aws:"))
  | { name: (.urn | split("::") | last), type, id }
' state.json
```

The state records inputs and outputs for every resource, so it also answers questions such as which task definition revision is live or which engine version Aurora reports. It does not capture manual changes made in the console after the deploy.
