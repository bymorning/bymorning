---
title: Microsoft Entra
description: Register ByMorning in Microsoft Entra ID, in the commercial cloud or Azure Government, and fix failed registrations and sign-ins.
---

ByMorning signs people in through a single-tenant Microsoft Entra app registration. The Gateway talks to Entra directly, so it needs outbound HTTPS to the Entra authority for your cloud.

| Cloud            | Portal                     | Authority                   | Issuer ByMorning derives                             |
| ---------------- | -------------------------- | --------------------------- | ---------------------------------------------------- |
| Commercial       | `https://portal.azure.com` | `login.microsoftonline.com` | `https://login.microsoftonline.com/<tenant-id>/v2.0` |
| Azure Government | `https://portal.azure.us`  | `login.microsoftonline.us`  | `https://login.microsoftonline.us/<tenant-id>/v2.0`  |

Register the application in the cloud where your users sign in. ByMorning does not support the multi-tenant `common` or `organizations` endpoints.

## Network

The Gateway reaches the authority on port 443 when you register the Auth Provider and on every sign-in: it reads `<issuer>/.well-known/openid-configuration`, exchanges the authorization code at the token endpoint, and reads the signing keys. All three live on `login.microsoftonline.com` (commercial) or `login.microsoftonline.us` (Azure Government). The browser also reaches the same authority.

A Gateway without that egress fails Setup with `ByMorning could not reach the identity provider at https://login.microsoftonline.us. Check that the Gateway has outbound HTTPS access to it.`

- **AWS in a restricted VPC:** if outbound traffic is limited to approved destinations, add the authority to the allowed egress.
- **Azure:** with `outbound_type = "userDefinedRouting"`, allow the authority on your firewall.

Microsoft publishes the authority's address ranges as the `AzureActiveDirectory` service tag, in separate files for the public cloud and US Government.

## Register

1. Open **Microsoft Entra ID** → **App registrations** → **New registration**.
2. Choose **Accounts in this organizational directory only** (single tenant).
3. Set the redirect URI platform to **Web** and enter the **Callback URL** that ByMorning Setup shows, exactly: `https://<host>/auth/callback/<providerID>`. Copy it from Setup; the provider ID is allocated there.
4. Under **Token configuration** → **Add optional claim**, choose token type **ID** and add `email` and `xms_edov`. Accept the prompt to add the Microsoft Graph `email` permission.
5. Under **Certificates & secrets**, create a client secret and copy its **Value**. Note its expiry.
6. Note the **Application (client) ID** and **Directory (tenant) ID** on **Overview**.
7. Under **Custom domain names**, verify every email domain you will admit in ByMorning.

ByMorning calls no Microsoft API. It requests only the OpenID Connect scopes `openid email profile` and needs no application permissions or other API permissions; it does not use the default `User.Read`. If your tenant blocks user consent, grant admin consent for those scopes. If the Enterprise application requires assignment, assign the users or groups who sign in.

## Configure

In Setup (first Auth Provider) or **Settings** → **SSO** → **Connect SSO**:

1. Choose **Microsoft Entra** as the OpenID Connect (OIDC) Provider.
2. Choose the **Microsoft Entra cloud**: Commercial or Azure Government.
3. Enter the **Microsoft Entra tenant ID**, **Client ID**, and **Client secret**.
4. Enter the admitted **Email domains** (Setup accepts a comma-separated list; Settings accepts one).
5. Save. ByMorning checks the tenant's discovery document before it stores anything.

A provider seeded from the `AUTH_*` environment variables uses the redirect URI `https://<host>/auth/callback` instead.

## Admission

ByMorning admits a person only when the ID token carries an `email` in an admitted domain and Entra vouches for it. Entra does not send `email_verified`; it sends the optional `xms_edov` claim (email domain owner verified), which is `true` only when the email's domain is verified in your tenant. ByMorning accepts `xms_edov: true` for the `email` in the same ID token. An explicit `email_verified: false` always refuses.

The account is linked to the token's stable `sub`, not to the email. These people are refused:

- Users without a `mail` attribute: Entra sends no `email` claim.
- Guests (`#EXT#` user principal names) and users whose email domain is not verified in your tenant: `xms_edov` is not `true`.
- Users whose email domain is verified in the tenant but not admitted in ByMorning.

## Troubleshooting

Setup and **Settings** → **SSO** report discovery failures with the issuer origin. Setup answers `503` for an unreachable issuer and `400` otherwise; Settings answers `400`.

| Message                                                                                                                                                           | Fix                                                                                                                          |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `ByMorning could not reach the identity provider at <origin>. Check that the Gateway has outbound HTTPS access to it.`                                            | Open Gateway egress to the authority; see [Network](#network). A TLS-intercepting proxy without a trusted CA looks the same. |
| `The identity provider's discovery document at <origin> did not match the issuer. Check the issuer URL.`                                                          | The tenant belongs to the other cloud, or the tenant ID is wrong. Choose the matching **Microsoft Entra cloud**.             |
| `The identity provider at <origin> did not return a valid discovery document for this issuer. Check the issuer URL.`                                              | The tenant ID does not exist in that cloud. Copy the **Directory (tenant) ID** again.                                        |
| `... does not list an authorization, token, and JWKS endpoint.`, `... authorization code flow.`, `... PKCE with S256.`, `... does not accept a client secret ...` | The issuer is not a standard Entra v2.0 tenant endpoint. Use the issuer ByMorning derives.                                   |

A failed sign-in returns to `/login?auth=failed&reason=<code>`, and the sign-in page explains the code. The Gateway logs `Authentication callback failed` with `stage`, `error`, `rejection`, and `reason`.

| `reason`   | Meaning                                                                                   | Fix                                                                                                                                                           |
| ---------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `claims`   | The ID token has no `email`, or Entra did not vouch for it                                | Add the optional ID claims `email` and `xms_edov`, verify the domain under **Custom domain names**, and give the user a `mail` attribute. Guests are refused. |
| `domain`   | The email domain is not admitted by this Auth Provider                                    | Add the domain in **Settings** → **SSO**, or sign in with an admitted address.                                                                                |
| `exchange` | The token endpoint was unreachable or refused the code, or the ID token failed validation | Check the client secret value and expiry, that the redirect URI matches exactly, and Gateway egress to the authority.                                         |
| `provider` | The Auth Provider was removed, disabled, or changed during the sign-in                    | Sign in again. Confirm the provider is enabled in **Settings** → **SSO**.                                                                                     |
| `expired`  | The sign-in attempt expired (10 minutes) or finished in another browser                   | Start again from the sign-in page in the same browser.                                                                                                        |
| `account`  | The account cannot be provisioned or is suspended                                         | Invite the person (invite-only installations) or restore the account.                                                                                         |
| `unknown`  | Anything else, including an Entra error returned instead of a code                        | Read the Gateway log line for `stage` and `error`.                                                                                                            |

Microsoft shows some errors before the browser returns to ByMorning:

- **`AADSTS50011`:** the redirect URI does not match. Register exactly the **Callback URL** Setup showed, including the provider ID.
- **`AADSTS700016`:** the application is not in that tenant. Check the client ID, the tenant ID, and the cloud.
- **`AADSTS50105`:** assignment is required and the user is not assigned.

A browser already signed in to another Microsoft account signs in as that account; use a private window.
