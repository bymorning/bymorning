ByMorning is a self-hosted gateway between AI and your internal systems. The ByMorning chat client, coding agents like Claude Code, and your own applications connect through it to reach Models and Tools. Every request is permission-checked and logged — who asked, what was accessed, what came back — and you configure Providers, integrations, permissions, policies, and budgets in one place.

## LLM gateway

Point applications at ByMorning using the OpenAI, Anthropic, and Google protocols they already speak. ByMorning routes each request to the configured Provider — self-hosted or cloud — and keeps Model availability, Provider selection, and spending controls in the Workspace, so you can swap Models without changing clients. See [Inference API](/developer-reference/inference-api) for endpoints and authentication.

## MCP gateway

Register internal Tools from MCP servers, then make them available through ByMorning's MCP gateway — the same permissions and authorized data for every client. Permissions control which actions each person and Agent may perform, policies apply session-aware rules to Tool activity, and every Tool call is recorded. See [Integrations](/configure/integrations) to connect a server, and the [Permission model](/developer-reference/permission-model) for inbound MCP.

## Configure

Define Models, integrations, permissions, policies, and budgets in [Workspace configuration](/configure). Choose the surface that owns the behavior you want to change.

## Console

Use [Members](/admin/members) to invite people, and [AI Gateway](/gateway/usage) to review usage and control Models for each Workspace.

## Architecture

Read [How the ByMorning gateway works](https://bymorning.ai/journal/gateway-under-the-hood) for a technical tour of the control plane, Model routing, Tool catalogs, Provider failover, permissions, budgets, and policy.
